Three states at every sample point.

At every sampled point, one of three things is true. A tool that adds the last two together as "not visible" reports the same figure for a scan that measured everything and a scan that failed, and the error runs in a direction nobody can see. The two scans below are that arithmetic, side by side.

Found

The business appeared in the results at that point, at a recorded rank. Filled means inside the top 3, hollow means below it.

Absent

The point was measured and the business was not in the list captured there. That is information, and it is as deep as the capture: points here captured between 1 and 10 rows, so absent means absent from a list of that depth.

Unreached

The point was never measured: a timeout, a block, a quota. That is a hole in the data, and the reason is recorded.

Merged the common way, both scans print the same number. Falloff prints a different figure for each, keeps the gaps out of the denominator, and refuses to publish the second one.

Dated studies, names withheld.

2 real scans, each observed on the date shown. Names withheld; coordinates, ranks and dates are in the snapshots.

Ranks were read from the Google Maps results feed in a logged-out desktop browser at zoom 13, in one pass. This was not the Places API, which measures a different surface. They were observed with an automated browser scan written by this project's author, which is not in this repository; this repository ships no scraper. The reproduce command on each study re-renders the recorded file, and re-observing those points needs your own provider. A scan through another provider is not comparable with these.

Each study is a single pass on one day. Nothing here measures how far a point moves between scans, because no study has been run twice; falloff compare is the command that would. The auditor recomputes the figures.

The auditor recomputes every figure from the raw readings, and replays the sampling geometry from the pins the file recorded. It is arithmetic only: no judgment, no model, no stated figure believed.

Below is the hero study with four edits someone might make to improve a result, then the verbatim output of the command. D4 is the geometry replay: the auditor rebuilds the sampling plan from the pins recorded in the method block and compares it with the coordinates, the distances, the bearings and the labels in the file. Here the outer radius pin was edited after the scan, so the rebuilt plan no longer lands on the recorded points. A3b catches a widened top-3 size, and C7 catches a point recorded as an absence whose own captured list contains the business.

A pass says the file is internally consistent. It does not say the readings are true, and the verdict line says so: some lies leave no trace in one file, and the README lists them under "what the audit cannot know".

Points allocated by circumference.

A uniform grid spends most of its budget far from the business, where nothing changes, and under-samples the near rings, where everything does.

Ring radii follow a geometric ladder from the inner to the outer radius. Points per ring rise with the radius, with a floor, so the outer ring is not mostly gaps. Each ring is rotated by the golden angle from the last, so points never line up into lanes that leave a wedge unsampled. The total is trimmed to an exact call budget, so the cost is known before the scan starts.

Get it, then choose how readings arrive.

The npm package is not published yet. Checked 2026-09-19: npm view falloff version returned 404 Not Found. Until it is, run it from a clone. Node 20 or later, no dependencies.

git clone https://github.com/CandyFlex/falloff
cd falloff
npm test
falloff() { node bin/falloff.mjs "$@"; }

The last line defines the command for your shell session, so the examples below run as written from the repository root. It is a POSIX shell function; in PowerShell, cmd or anywhere else, run every example as node bin/falloff.mjs <args>.

Falloff ships the method, not a scraper. Nothing in it drives a browser against anyone's site. Readings come through a provider, and each one has a limit worth knowing first.

Manual sheet

no key

The limit: one person, one browser, one pass. It is as good as the care taken with the sheet. A row left blank is recorded as unreached, never as absent.

falloff plan --lat 25.81 --lng -80.2 --query dentist --preset mid \
             --out out/plan.json --sheet out/plan.csv
falloff ingest --plan out/plan.json --sheet out/plan.csv \
               --name "Some Business" --observer JO --out out/manual.json

plan writes a sheet of map links. Open each in a logged-out window, write found and the rank, or absent, then ingest turns the sheet into an audited snapshot.

OpenStreetMap

no key

The limit: OpenStreetMap has no ranking. This provider sorts listings by distance from each sample point, so it measures listing proximity in the open map. It is not Google rank and not what Google shows anyone.

falloff scan --provider osm --name "Some Business" --id osm:node/123456 \
             --lat 25.81 --lng -80.2 --query dentist --preset mid --out out/osm.json

The public Overpass server is shared and it throttles. A point it refuses is recorded as unreached with the reason. Retrying throttled calls has been tested offline only, not yet against the live server.

Google Places API

your key

The limit: it needs your own key, and Google bills above its free monthly cap, so check the current pricing page before a wide preset. It measures the Places API. The studies on this page were read from the Maps results feed in a browser, which is a different surface, so the two are not comparable.

export FALLOFF_PLACES_KEY=...
falloff scan --name "Some Business" --id <place-id> --lat 25.81 --lng -80.2 \
             --query dentist --preset mid --out out/scan.json

The key is never written to the snapshot. The recorded reproduce command drops it.
